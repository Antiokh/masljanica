# Масляница · Белград

**Приложение:** [masljanica.pages.dev](https://masljanica.pages.dev/)

Публичное приложение фестиваля: Astro 5 + Starlight, статическая генерация, русский интерфейс, светлая/тёмная тема, мобильная навигация, Pagefind и PWA.

```sh
npm install
npm test
npm run dev
npm run build
npm run preview
```

Node.js 22.12+. Cloudflare Pages: команда `npm run build`, каталог `dist`, без серверного адаптера. Приложение рассчитано на корень домена.

## Контракты сопровождения

Перед изменениями читать [AGENTS.md](AGENTS.md). Подробные источники истины: [PWA и навигация](docs/PWA.md), [layout и меню состояния](docs/LAYOUT.md), [песенник](docs/SONGS.md). Краткое описание ниже не заменяет эти контракты и их регрессионную матрицу.

## Контент

`src/data/` — нормализованные публичные данные из Glide. `scripts/generate-content.mjs` генерирует Markdown-страницы из данных до запуска Astro. Slug — человекочитаемый идентификатор; исходные ID сохраняют связи сценария. CRM, идентификаторы исполнителей, отзывы и бронирования исключены.

Аудио архивируется в `public/media/audio/` через GitHub Actions **Archive audio** (`scripts/archive-audio.py`). Отчёт `src/data/audio-archive.json` хранит оригинальные URL, локальные пути, размер, SHA-256, длительность и ошибки. Генератор страниц использует локальные копии при наличии, иначе исходные URL. Офлайн-кэш включает архивированные MP3 и поддерживает Range-запросы для перемотки. YouTube и внешние иллюстрации остаются онлайн. Публикация записей в открытом репозитории предполагает наличие прав на их распространение. Изображений мастер-классов в CSV не было. Главная — адаптивная афиша и каталог материалов. Сезонные параметры управляются frontmatter `src/data/home.md`; просроченное расписание скрывается даже в сохранённой офлайн-копии. Социальные ссылки и расширенный исторический текст требуют отдельного восстановления.

Флаги active сохранены как метаданные, все песни и игры доступны в каталоге; неподтверждённые мастер-классы помечены «Уточняется».

Сборка генерирует версионированный Service Worker из фактических файлов dist. Офлайн проверяется в production preview, не в dev.

## Дизайн

Утверждённая палитра «Зимний день / Зимняя ночь» задана в `src/styles/app.css`: белый и ледяные поверхности днём, сине-графитовые ночью, тёплый красный днём, яркий кармин ночью и золотистые декоративные акценты. Мобильная навигация — четыре равные CSS Grid-колонки (Избушка, Песни, Игры, Ещё), с учётом safe area. Существующие маршруты и материалы сохранены.

## Быстрая навигация и офлайн

Принципы RSLive адаптированы для небольшого статического приложения: Astro ClientRouter + prefetch по намерению, один browser runtime с `astro:page-load`, лёгкий Service Worker и отдельная полная офлайн-копия по явной команде. После первой загрузки страницы текущей версии читаются из runtime-кэша; проверенная полная копия текущей версии обслуживается без сетевого запроса. Обновление полной копии копирует неизменившиеся ревизии и проверяет SHA-256 новых файлов перед атомарной сменой активного указателя. Старый архив сохраняется при ошибке. Установка PWA и загрузка полной копии разделены. Из RSLive перенесён чистый daily resolver: отдельное подтверждение локального хранилища, не более одного предложения установки/скачивания/обновления за локальный календарный день, автоматическая поддержка офлайн-копии по явному переключателю. Отключение автоматических обновлений не удаляет копию; удаление также отключает автообновление.

После изменения runtime проверять production build, переходы туда/обратно, поиск и фильтры, тему, холодный офлайн-старт, Range-аудио и обновление/удаление копии.

Песенник `/songs/` — компактный список с независимыми play/pause, раскрываемыми текстами, выбором исполнения и видео по явному нажатию. Ссылки из сценария открывают песню в списке через hash. Старые страницы песен остаются для прямых ссылок и Pagefind. Обработчики делегированы, аудио загружается по требованию (`preload=none`).

### Внешние эмбеды

По аналогии с [MapEmbed RSLive](https://github.com/Antiokh/rslive.ru/blob/main/astro/docs/components/map-embed.md) внешнему iframe не назначается src до решения о сети. Песенник, старые страницы песен и игры используют один runtime `public/external-embeds.mjs`. Холодный офлайн-старт не создаёт iframe; при потере сети на открытой странице блок скрывается и внешний плеер удаляется (для видео, в отличие от уже загруженной карты, буфер не гарантирует доступность). При восстановлении сети возвращаются элементы управления, на отдельных страницах — lazy iframe, в песеннике — кнопка. Тексты и локальное аудио не зависят от этого состояния. Проверки в Playwright используют локальный mock провайдера и online/offline transitions.

На desktop (>60rem) переключатель темы перенесён из RSLive (`ThemeSwitch.astro`, light/auto/dark); на мобильных остаётся штатный ThemeSelect. Оба используют `starlight-theme`, с синхронизацией при SPA-переходах.

### Быстрая навигация: cache hot path

Service Worker использует ревизии текущей сборки, поэтому неизменённые файлы из предыдущей полной копии обслуживаются сразу. Runtime cache ограничен фактическими путями сборки; запись ответа в Cache Storage выполняется вне критического пути. Основные разделы предварительно загружаются после первого отображения, по одному, без аудио и при отключённой экономии трафика. При известном offline сеть не опрашивается. Измерение в DevTools: `performance.getEntriesByName('masljanica-nav-swap')` (время от подготовки Astro до DOM swap, не полный cold-load). Регрессионный тест проверяет, что навигация не ждёт медленной записи в кэш и не запрашивает неизменённые страницы из старой копии.

### Интерфейс и восстановление PWA

Сверено с RSLive: [layout](https://github.com/Antiokh/rslive.ru/blob/main/astro/docs/components/layout.md), [PWA](https://github.com/Antiokh/rslive.ru/blob/main/astro/docs/PWA.md). Компонент `PwaStatus.astro` содержит логотип (пока /icon.svg), индикатор standalone и единое компактное меню с пятью строками, корзиной и двухпозиционным switch. На desktop меню открывается hover/focus/click, на mobile — нажатием на логотип либо через первый блок «Ещё». `pwa-presentation.mjs` только отображает состояние, не управляет загрузкой. Индикатор, прогресс по числу файлов, статус и настройки синхронизируются одним runtime. Хранилище — оценка всего origin. Детерминированный staging сохраняется после прерывания; повторный запуск проверяет сохранённые файлы, переиспользует неизменённые, повторяет отложенный хвост и активирует только полную копию. Удаление очищает активную и незавершённую копии, а не обычный runtime cache. Отключение автообновления сохраняет данные. Специфичные для карт и Workbox механизмы не копируются.

### Плейлист песен

Все записи песен разрешаются строго в локальные MP3 по аудиоархиву; сборка проверяет наличие каждого файла. Общий нативный плеер находится вне раскрываемых текстов. Нажатие Play выбирает запись и начинает очередь в порядке списка (включая варианты исполнения); завершение записи автоматически запускает следующую. Предыдущая/следующая, пауза и перемотка управляют одним аудиоэлементом. Поиск не меняет очередь; при уходе с песенника воспроизведение прекращается. Браузерный тест проверяет фактическое продвижение currentTime онлайн и офлайн, а также автоматический переход к следующей записи.

Плеер песен: нативный audio скрыт, управление через Play/Pause строки и раздвижные капсулы вариантов. Неактивная запись — номер в круге, выбранная занимает свободную ширину и показывает время; прогресс по окружности. Нажатие варианта сразу воспроизводит его; при окончании очередь продолжается. Анимация отключается при prefers-reduced-motion.

В выбранной капсуле — отдельный нативный range для перемотки, синхронный с круговым прогрессом; перемотка не меняет play/pause. Неактивные варианты скрывают range из фокуса (`inert`).

Верхний компактный sticky-плейлист всегда доступен: предыдущая/следующая запись, Play/Pause, перемотка и текущий трек. Он использует тот же аудиоэлемент и состояние, что и капсулы. Раскрытая песня имеет единую поверхность и рамку с текстом и материалами.
