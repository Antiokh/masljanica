# Песенник: продуктовый контракт и архитектура

Утверждён владельцем 26.11.2026 после серии итераций интерфейса. Базовая реализация: [732c254](https://github.com/Antiokh/masljanica/commit/732c2543a3ff54d809c2e22f2b6d9f81f9b3c9a3).

## Зачем изменили старый интерфейс

Glide-подход требовал сначала открывать карточку песни, затем искать запись и возвращаться в каталог. На празднике это лишние действия: участнику нужно быстро запустить музыку, прочитать слова и при необходимости выбрать исполнение, в том числе без интернета.

Поэтому /songs/ стал песенником, а не каталогом ссылок. Основной сценарий — слушать и читать прямо в списке. Сохранённые отдельные страницы обслуживают старые ссылки и Pagefind, но не являются основным способом работы с песнями.

## Утверждённая композиция

- Поиск по названию и словам песни. Ниже — общий компактный плейлист, затем список.
- Плейлист виден до первого запуска и остаётся сверху при прокрутке. Показывает текущую песню, номер записи внутри неё, позицию во всей очереди, время, Play/Pause, предыдущую/следующую запись и горизонтальную перемотку.
- Каждая песня — отдельная карточка с собственным контуром, скруглением и небольшим промежутком до соседних. Слева круглый Play/Pause, справа chevron; название также раскрывает текст. Воспроизведение и раскрытие независимы.
- Раскрытая карточка имеет одну общую поверхность для заголовка, вариантов, текста и дополнительных материалов. Заголовок не отделяется от собственного контента другой заливкой или горизонтальной границей. Играющая песня выделяется контуром акцентного цвета.
- Варианты исполнения — горизонтальная группа раздвижных капсул. Неактивные варианты — компактные круги с номерами. Выбранный занимает свободную ширину, показывает Play/Pause, номер записи, длительность/текущую позицию и горизонтальную перемотку. Нажатие номера сразу запускает соответствующую запись. Ширина плавно перераспределяется; при prefers-reduced-motion анимация отключена.
- Иконка Play/Pause строго центрирована в круге, отделена от текста небольшим отступом. Прогресс по окружности показывается и на строке, и на выбранном варианте, и в общем плеере. Горизонтальный scrubber на широкой капсуле располагается между названием и временем, по вертикальному центру. На узкой — в средней строке, между названием и временем. Круговой и горизонтальный прогресс используют реальное время одного транспорта.
- Перемотка — отдельная зона нажатия (native range), доступная мышью, touch и клавиатурой; она не переключает Play/Pause. У свёрнутых вариантов содержимое inert, отсутствует в Tab-порядке.
- Насыщенный терракотовый #A94318 для выбранного состояния и воспроизведения ночью, янтарный #F9A04B для текста и акцентных деталей; тёплая киноварь #C34D21 днём, белые иконки/текст; приглушённые оттенки предназначены для вторичных поверхностей. Не заменять активные состояния малоконтрастными заливками. Обе темы используют общие CSS variables.
- Не возвращать dropdown вариантов, стандартный видимый браузерный audio controls, отдельные плееры на строках или обязательный переход на detail page.

## Архитектура и причины решений

| Компонент | Ответственность и причина |
| --- | --- |
| src/pages/songs.astro | Статическая разметка списка, общий плейлист, варианты, lyrics, данные очереди. Не требует клиентского запроса к API. |
| src/data/songs.json | Названия, slug, тексты, порядок вариантов и исходные URL. Сохраняет исходные идентификаторы. |
| src/data/audio-archive.json | Соответствие исходных ссылок локальным MP3, длительность, контрольные суммы. Все song tracks разрешаются строго в /media/audio/*.mp3; отсутствие файла — ошибка сборки. |
| public/song-list.mjs | Один транспорт, очередь, выбор варианта, play/pause, seek, синхронизация всех представлений, lifecycle Astro. |
| src/styles/app.css | Единая палитра, геометрия карточек, капсул, иконок, кольцевого прогресса и sticky-плейлиста. |
| public/external-embeds.mjs | Видео по явному нажатию, скрытие/удаление внешнего iframe офлайн. Локальное аудио и текст не зависят от этого модуля. |

Один attached native audio (#song-player-audio, preload=none, hidden, вне details) служит источником истины. Верхний плейлист, кнопка строки и варианты — разные органы управления тем же элементом. Это исключает конкурирующие экземпляры, рассинхронизацию позиции и остановку при закрытии details. Play вызывается синхронно из пользовательского действия (mobile autoplay policy); состояние отображается по native media events. Ошибки показываются через role=status.

Очередь — алфавитный порядок каталога, внутри песни исходный порядок записей. Поиск только скрывает строки и не меняет очередь. ended запускает следующий track при наличии; последний останавливается. При уходе из песенника воспроизведение прекращается (глобальный межстраничный плеер пока не утверждён). Перемотка не меняет состояние play/pause текущей записи; перемотка ещё не запущенного варианта подготавливает его без autoplay.

Сценарий ссылается на /songs/#slug. Hash открывает соответствующий текст, но не запускает музыку. Обработчики делегированы и учитывают astro:page-load / before-swap. Локальные записи включены в проверяемую офлайн-копию; Range-запросы обслуживает SW. Не подменять локальные MP3 исходными внешними адресами. Подробности — [PWA](PWA.md).

## Регрессионная защита

- npm test — проверки данных, PWA, навигации и транзакций.
- npm run build — реальные локальные MP3 и production offline manifest.
- node scripts/smoke-offline.mjs — реальный Chromium, SPA, поиск, общий плеер, переключение записей, currentTime, круговой прогресс, seek, синхронизация, окончание, cold/hot offline и Range. Отдельный модуль scripts/assert-song-layout.mjs проверяет вычисленные стили и геометрию при 390 и 1440 CSS px в light/dark.
- Визуальная QA: проверить также 320 и 768 px, реальный touch, длинные названия, все пять вариантов, скриншоты обеих тем. Не считать успешный build доказательством визуальной корректности.

Тесты проверяют свойства, а не пиксельное совпадение. Не ослаблять их только ради зелёной сборки. Изменение утверждённого поведения требует явной задачи и совместного обновления документации и тестов. Увеличение каталога допустимо: не фиксировать количество записей в продуктовой логике. Фактические проверки сообщать отдельно от заявленных контрактов.

На desktop от 60rem песенник — master-detail: слева алфавитный список с быстрым Play/Pause, справа выбранная оригинальная карточка. Общий sticky-плеер и поиск на всю ширину; независимая прокрутка панелей. Выбор не запускает музыку. На mobile исходные аккордеоны. Контроллер catalog-master.mjs не клонирует контент и не перестраивает очередь.
