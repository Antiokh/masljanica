# Layout и дизайн-система

См. [PWA](PWA.md) для состояния и [песенник](SONGS.md) для специализированных контролов. Эталон компактного статуса: [RSLive layout](https://github.com/Antiokh/rslive.ru/blob/main/astro/docs/components/layout.md).

## Общая система

Утверждены зимний день (белый фон, холодные светлые поверхности, тёплая киноварь #C34D21) и зимняя ночь (сине-графитовые поверхности, янтарный #F9A04B для текста, иконок и прогресса; терракотовый #A94318 для выбранных элементов и активных действий с белым текстом). Вторичные оттенки ночью: #3B2D20 и #FFC27C. Золото #EBC47B ночью и #E9B44C днём, фоны и нейтральные поверхности остаются прежними. Вторичные оттенки днём: #FFF1E8 и #8D3618. Основные цвета задаются CSS variables в `src/styles/app.css`, не локальными копиями палитры. Сохранять контраст и читаемость. Не возвращать золотую тему Glide или угольно-чёрный фон. Темы light/auto/dark совместимы со Starlight: ключ starlight-theme, data-theme содержит resolved light/dark. Desktop ThemeSwitch, mobile ThemeSelect; синхронизация при смене OS, storage и SPA.

Браузерная подсветка касания (`-webkit-tap-highlight-color`) прозрачная во всём приложении. Сохранять собственные активные состояния и видимый акцентный `:focus-visible` для клавиатуры; не отключать выделение текста и не удалять фокус глобально.

## Шапка и навигация

`Header.astro` владеет компоновкой, `PwaStatus.astro` — логотипом и меню состояния. Header flex: бренд с min-width:0 и ellipsis, controls с фиксируемой шириной; иконки в одинаковых hit areas. На мобильных (до 60rem включительно) основное меню фиксировано снизу: repeat(4,minmax(0,1fr)), Избушка / Песни / Игры / Ещё. Summary «Ещё» занимает такую же ячейку, как ссылки. Одинаковая вертикальная геометрия, gap, размеры SVG и padding; активный раздел подсвечен. Учитывать safe area и отступ контента, не закрывать последнюю строку. На desktop меню в шапке: центральный блок `.header-navigation` объединяет основную навигацию и поиск, переключатель темы остаётся справа в `.header-actions`. На mobile навигация фиксирована снизу, единственный экземпляр Search остаётся в верхней шапке между брендом и темой с горизонтальными padding по .375rem и межблочным gap шапки. Не дублировать Search между breakpoint: его dialog и keyboard shortcut должны иметь одного владельца. `FestivalSearch.astro` содержит единственный SSR input и native dialog (на mobile fullscreen, на desktop компактная панель). `festival-search.mjs` — делегированный SPA-safe controller поверх штатного Pagefind index. Не возвращать Starlight 0.35 Search с инициализацией только по DOMContentLoaded: после SPA swap его новый dialog остаётся пустым. Поле доступно сразу, загрузка движка только по намерению, явные loading/empty/error states; Escape, Ctrl/Cmd+K, focus restore, закрытие при выборе результата или swap. Локальные фильтры каталогов независимы. Не возвращать «Частушки» в меню.

Контекстная шапка на всех ширинах: главная — «Масляница» / «Белград · дата» (дата из home.md, видна только при активном событии); остальные маршруты — заголовок текущей страницы из Starlight route data / «Масляница». Ссылка ведёт на главную. Семантический H1 сохраняется в контенте для доступности и поиска, но визуально скрыт; отдельная панель H1 не занимает высоту и не создаёт разделитель. На mobile основной контент начинается с .7rem отступа, поиск и sticky playlist компактнее. Нижняя навигация 3.375rem (54 CSS px при 16px root) плюс фактический safe area, внутренний вертикальный padding .125rem, целевая высота hit area не менее 44px; одна резервная зона в `.main-pane > main`, без дублирующего padding на body; четыре равных ячейки сохраняются. Пустой штатный Footer Starlight заменён `AppFooter.astro` без разметки: даже отключённые функции оставляли `.meta` с margin-top:3rem и дополнительный sibling margin. Реальная авторская подпись на главной сохраняется. Последний content panel имеет нижний отступ .3rem на mobile. При прокрутке до конца между последним элементом длинного списка и верхом нижней навигации остаётся не более 12 CSS px в обычном viewport. Системная панель браузера не принадлежит приложению. Не менять утверждённые цвета.

## Telegram Mini App

Единственный адаптер `public/runtime-environment.mjs` определяет Telegram по параметрам запуска/сессионному контексту, не по user agent или одному глобальному объекту. Это признак среды для UI, не авторизация. Официальный Telegram WebApp SDK загружается только в Mini App; при ошибке SDK остаются локальный контент и тема запуска. В auto используются colorScheme и реальные themeParams Telegram: фон, текст, вторичные поверхности, секции, разделители, ссылки, кнопки и нижняя панель. Explicit light/dark возвращают фирменную палитру и сохраняют приоритет; обычный браузер/PWA продолжает использовать ОС. Тема запуска захватывается в AppHead до ClientRouter, там же начинается условная загрузка SDK. Не заменять полученную тему запуска неподтверждённым default colorScheme SDK: использовать themeParams или подтверждённое событие themeChanged. При pageshow, visibilitychange, focus и online запрашивать актуальную тему через web_app_request_theme; синхронизировать SPA и существующие контролы. На /offline/ показывать режим, входную тему, источник и фактически применённую тему. `telegram-palette.mjs` валидирует RGB-токены и применяет их только в auto; CSS `data-telegram-palette=active` связывает их с существующими переменными Starlight и Масляницы. При отсутствии bg_color действует прежняя палитра как резерв. Смена цветов внутри той же light/dark темы также обновляет UI и native chrome. Launch colors применяются в AppHead до SDK; событие activated обновляет тему при возврате. Декоративное золото иллюстраций сохраняется. Обычный браузер и ручные темы не меняются. При ширине до 60rem визуальная шапка скрыта, её DOM остаётся доступен контроллеру; нижнее меню, единые поиск и PWA popover остаются. В «Ещё» — поиск и селектор темы. Автоматический режим в Telegram подписан «Telegram», в обычном браузере — «Авто»; внутреннее значение `auto` и ключ хранения `starlight-theme` не меняются. На широком экране шапка сохраняется. Insets из Telegram API и CSS safe area согласуются без двойного резерва; sticky playlist использует ту же переменную высоты верхней зоны. Не загружать SDK в обычном браузере.

### Telegram Back navigation

Контракт перенесён из [DOBRI docs/NAVIGATION.md](https://github.com/Antiokh/dobri-visarun/blob/48e84f31ffe3f2e26c6bddb18a21140b86b5605e/docs/NAVIGATION.md) и [src/lib/telegram.ts](https://github.com/Antiokh/dobri-visarun/blob/48e84f31ffe3f2e26c6bddb18a21140b86b5605e/src/lib/telegram.ts), адаптирован для Astro ClientRouter в `public/telegram-back.mjs`. Инициализация только из runtime-environment после подключения Telegram SDK, один native callback и один popstate handler. Приоритет: глобальный поиск → диалог персонажа → PWA popover → «Ещё» → родительская страница. «Избушка», «Песни», «Игры» — равноправные корни; «Сказ», «Мастера», «Частушки», «Офлайн» возвращают к последнему корню (при прямом открытии — Избушка); вложенные страницы возвращают на уровень выше. Inline accordion песен не является отдельным экраном. BackButton показывается только при внутреннем действии. Native Back закрывает один уровень, system Back на корне вызывает Telegram close. В Telegram внутренние route links используют Astro history replace; одна guard-пара перехватывает системный Back до Astro popstate, сохраняет его index/scroll state и восстанавливает текущий URL перед SPA-переходом. Не создавать guard для каждого перехода и не подменять стандартную историю браузера/PWA. Проверять обе кнопки, закрытие overlay, прямые вложенные ссылки, повторные переходы, отсутствие роста history и офлайн-навигацию.

## PWA status

Логотип в шапке и солнце на афише используют единую предоставленную владельцем прозрачную иллюстрацию `/media/maslyanica-sun.webp`. Векторный `/icon.svg` сохранён для favicon и PWA manifest. Не добавлять искусственную квадратную подложку. Размер frame 2.75rem desktop / 2rem mobile, object-fit:contain. Не привязывать геометрию к внутренним пропорциям изображения. Точка состояния в левом нижнем углу логотипа (не отдельная колонка); видима в standalone. Цвет: green online, blue offline + ready, red offline + unavailable, neutral gray unknown/download/delete. Приоритет busy над обычным состоянием. Не использовать акцент бренда для синего ready.

Единственный native popover `#festival-pwa-menu`, оба триггера используют один panel. Desktop — hover, keyboard focus, click; на mobile — tap по логотипу или status/⋮ первым блоком «Ещё». Позиционировать относительно фактического anchor: ниже верхнего логотипа при наличии места, выше нижнего триггера при необходимости, clamp к viewport. Не фиксировать экранные координаты и не наращивать z-index вместо top layer. Сохранять focus, Escape, light dismiss, повторный click; hover → click фиксирует уже открытое меню, а не закрывает его. На SPA swap закрывать menu и не оставлять ссылки на старые DOM nodes.

Пять строк с единой сеткой:
1. Подключение — Онлайн / Офлайн · копия доступна / Офлайн · копии нет / проверка.
2. Запуск — Браузер / Приложение.
3. Офлайн-копия — Готова / Устарела / Не скачана / Проверяем / Загрузка или Обновление N% / Удаление; рядом маленькая корзина.
4. Автообновление — двухпозиционный switch, без отдельной страницы для его включения.
5. Хранилище — оценка navigator.storage.estimate().usage всего origin, не точный размер pack.

Лейблы слева, значения и compact controls справа. Выравнивание строк по вертикальной оси, стабильные hit areas, текст может переноситься без горизонтального overflow. Не добавлять громоздкие action buttons, служебные сведения о регистрации SW или отдельную строку stage. Ссылка «Подробнее» и компактное действие Скачать/Обновить в footer. Прогресс по файлам, подпись «Прогресс · материалы», indeterminate до известного total. Тонкая линия занимает всю ширину внешней шапки Starlight от края до края, по её нижней границе (не по нижней границе внутреннего `.app-header` с padding). `.pwa-nav-progress` — sibling внутренней шапки; дорожка прозрачная, fill использует `--sl-color-accent` в обеих темах. Нативный progress стилизуется через appearance:none и WebKit/Firefox pseudo-elements, не только accent-color; indeterminate также использует акцент, с учётом prefers-reduced-motion. Те же цветовые правила действуют в popover, «Ещё» и на /offline/. Mobile status в «Ещё». В idle progress скрыт. Корзина disabled при отсутствии pack/staging, во время подготовки или удаления. Auto off сохраняет копию.

Presentation runtime получает модель из app.js; ни поповер, ни мобильное меню, ни /offline/ не определяют состояние самостоятельно. Storage estimate запрашивать по открытию/существенному изменению, не на каждом переходе.

## Песенник

Утверждённая композиция и rationale — [SONGS](SONGS.md). Общий sticky-плейлист, единые поверхности раскрытых песен, раздвижные капсулы и насыщенные активные состояния сохраняются при изменении общих стилей. Общие токены: --festival-selected = var(--festival-action) в обеих темах, --festival-selected-text = #FFFFFF; --festival-action — #A94318 ночью и #C34D21 днём. Не менять утверждённую светлую палитру при коррекции ночной темы. Не возвращать приглушённую заливку выбранных элементов. Геометрия проверяется отдельным модулем в production smoke.

## QA

Smoke проверяет desktop/mobile смену темы, hover/click/Escape, horizontal bounds меню при 390 px. Для layout-изменений обязательны реальные скриншоты/осмотр при 320, 390, 768 и 1440 px, обе темы, browser и standalone, длинные значения, loading/ready/stale/error и нижнее меню. Проверять одинаковые размеры четырёх hit areas, выравнивание корзины/switch и отсутствие скачков строк, clipping, наложений на theme/search и перекрытия контента. Проверить клавиатурный Tab/Shift+Tab, Escape и touch. Наличие smoke не подтверждает визуальную QA.

## Главная / Избушка

Постоянная часть: афиша бренда без просроченной даты, шесть ссылок (Песни / Игры / Сказ / Мастера / Блины / История), компактная витрина включённых мастер-классов, оригинальное предисловие и сворачиваемый краткий сюжет из Glide. Сезонная часть: год, дата, время, место и отдельная программа. На всех экранах единый вертикальный порядок: афиша → три информационных аккордеона → программа → бесплатный вход/донейшн → навигационные карточки → краткая витрина мастер-классов. На mobile две колонки × три ряда, desktop три колонки × два ряда. Навигационные карточки компактные горизонтальные: иконка слева, название и описание справа, вертикальное центрирование, без лишних отступов; геометрия проверяется при 320/390/1440 px. Программа занимает всю ширину и скрывается независимо. Исторические аккордеоны переиспользуют FestivalIntro.astro вместе со сказом; краткий сюжет добавляется слотом только на главной. Использовать существующие theme tokens; крупное оригинальное солнце на афише — `/media/maslyanica-sun.webp`, тот же обязательный локальный ассет, что и в шапке. При отсутствии файла сборка завершается ошибкой. Оба формата локальные, входят в offline pack. Не добавлять декоративную рамку вокруг солнца; портреты локальные WebP из public/media/characters по character-archive.json; карточки 4:5 с изображением на всю площадь и акцентной плашкой имени, описания в native dialog без перехода. При отсутствии локального файла остаётся буквенный placeholder без внешнего запроса. CharacterGallery используется только в /scenario/#story-characters; диалоги создаются один раз в сказе. Старый /characters/ перенаправляет к галерее, отсутствует в меню и списке прогрева навигации. Старые detail pages не генерируются. Не дублировать крупный заголовок Starlight (он остаётся доступным для screen reader).

Настройки — YAML frontmatter `src/data/home.md`: event.enabled, event.date (ISO YYYY-MM-DD в кавычках), event.timezone (Europe/Belgrade), event.schedule. Это единственный источник даты; event.json — адрес и координаты; schedule.json — HH:mm без даты. Программа отображается только при enabled && schedule && дата не прошла по календарю Белграда; день мероприятия включён целиком. Сезонные блоки SSR hidden, runtime `public/home-season.mjs` применяет состояние на cold/SPA/pageshow/visibility и каждые 30 секунд на открытой главной. Проверка локальная, без запроса к серверу. Программа не индексируется Pagefind отдельно от runtime. Изменения настроек требуют сборки, но естественное истечение даты работает и в старой offline копии. При отключении расписания остальные данные афиши сохраняются; при отключении события остаются материалы и постоянная афиша. Тесты: scripts/test-home-season.mjs и production smoke.

## Сказ

Два обычных аккордеона истории и названия без декоративной плашки; части сказа с общим фоном заголовка и текста и достаточными внутренними отступами. Реплики с портретами и цветами ролей; ремарки отдельно; музыкальные вставки с локальным аудио. См. [STORY](STORY.md).

Главная: восстановлены локальная ссылка «Добавить в календарь» (/event.ics, UTC из настроенного часового пояса), компактная шкала времени: начало каждого пункта и отдельная строка завершения праздника; промежуточное окончание показывается только при несовпадении с началом следующего этапа, сезонное уведомление о бесплатном входе и добровольном донейшне, ссылки на историю, написание названия и подтверждённую страницу RSLive. Не возвращать дату со скриншотов 2026 года. URL социальных сетей и старых кнопок пока не восстановлены.

Календарь: как в Dobri Visarun, одна кнопка раскрывает Apple Calendar и Google Calendar. Apple — прямой собственный HTTPS /event.ics (offline download), Google — TEMPLATE URL; общая модель события src/lib/event-calendar.mjs, единый UTC диапазон с учётом Europe/Belgrade. В Telegram обе онлайн-ссылки используют WebApp.openLink; вне Telegram обычная ссылка. Back сначала закрывает выбор календаря. Google скрывается offline. Не использовать Blob/object URL, сторонний ICS-генератор или отдельную дату в ссылке. Тест scripts/test-calendar.mjs.

Афиша: увеличенное солнце (64–100 CSS px) в правом верхнем углу заголовка; компактные строки без лишнего вертикального интервала; ниже две полноширинные строки: иконка календаря слева, дата/время справа; иконка карты слева, адрес справа. Иконки одинакового размера и выровнены по левому краю. Календарь сохраняет оформление кнопки; значок карты — простая пиктограмма без рамки и подложки, в том числе при наведении. Вся строка даты раскрывает календарь, вся строка адреса открывает карту. Офлайн адрес остаётся видимым в той же компоновке без ссылки. Текстовые подписи действий не дублируются (доступные имена остаются). Выбор Apple/Google раскрывается под первой строкой; сезонное скрытие и offline сохранены. Production smoke проверяет фактическую геометрию.

Внизу главной WorkshopPreview.astro показывает все enabled мастер-классы из workshops.json и локальных иллюстраций workshop-details.json: название, ведущая, миниатюра. Ссылки /workshops/#slug раскрывают соответствующее занятие; отдельная ссылка на полный каталог. Нет неподтверждённых занятий, повторных описаний и собственного runtime. Галерея героев перенесена в /scenario/ перед частями сказа.

В аккордеоне «Наша масляница» первым элементом перед вступлением отображается общая иллюстрация персонажей `public/media/all-characters.webp` (1536×1024), на всю ширину контента, без обрезки и подписи, с небольшим отступом. Локальный файл обязателен: отсутствие вызывает ошибку сборки. Он входит в offline manifest; smoke проверяет наличие, порядок и пропорции. Строки программы вынесены в HomeProgrammeRow.astro, чтобы не вкладывать условную разметку с индексом в Astro map callback.

Частушки — шуточный дополнительный раздел `/ditties/`, ссылка «…частушки?» в правой части заголовка «В нашей избушке» использует тот же приглушённый стиль, что «Все мастер-классы». Не добавлять плитку или пункт меню. Оригинальные тексты `src/data/ditties.json` отображаются без редактуры, с авторской подписью; фольклор из `src/data/ditties-folk.json` отделён и снабжён источниками. Фильтры «Все», «Наши», «Народные», «Заветные», поиск, переносы строк сохранены. См. [DITTIES](DITTIES.md). Telegram Back возвращает на главную при входе оттуда; офлайн-копия включает страницу. Smoke проверяет тексты, доступность офлайн и Telegram Back.

Ссылки в программе определяются флагами `classes` и `games` в schedule.json. В 12:20 («Игры, конкурсы, выступления») показываются «Игры» и «Мастер-классы» в одной строке с переносом на узких экранах; в 11:30 сохраняется только «Мастер-классы».

Блины — `/pancakes/`, плитка «Блины · Печём и угощаем» на главной. Вступление о волонтёрском приготовлении и приглашение приносить свои блины; далее место для рецептов из книги владельца. Пока книга не предоставлена, не публиковать вымышленные рецепты или сведения об источнике. Страница доступна офлайн, Telegram Back ведёт к последнему корню.

История — `/history/`, восемь раскрываемых глав по источникам XIX века, с указанием страниц. Песни используют StoryMusic, существующие локальные аудио и один transport; игры ведут в соответствующую карточку каталога. Исторические иллюстрации с атрибуцией, локальный архив WebP, до его готовности — загрузка по желанию только онлайн. Блины — 24 рецепта книги 1854 г., сгруппированные в блины (11) и оладьи (13), современное изложение без добавления неуказанных мер. См. [HISTORY](HISTORY.md).
