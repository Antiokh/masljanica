# Layout и дизайн-система

См. [PWA](PWA.md) для состояния и [песенник](SONGS.md) для специализированных контролов. Эталон компактного статуса: [RSLive layout](https://github.com/Antiokh/rslive.ru/blob/main/astro/docs/components/layout.md).

## Общая система

Утверждены зимний день (белый фон, холодные светлые поверхности, тёплый красный #C43D32) и зимняя ночь (сине-графитовые поверхности, яркий красный #FF5548 без розового подтона для текста, иконок и прогресса; прежние насыщенные #B5232C для выбранных элементов и #C32935 для активных действий с белым текстом). Бледный коралл в тёмной теме не использовать. Основные цвета задаются CSS variables в `src/styles/app.css`, не локальными копиями палитры. Сохранять контраст и читаемость. Не возвращать золотую тему Glide или угольно-чёрный фон. Темы light/auto/dark совместимы со Starlight: ключ starlight-theme, data-theme содержит resolved light/dark. Desktop ThemeSwitch, mobile ThemeSelect; синхронизация при смене OS, storage и SPA.

## Шапка и навигация

`Header.astro` владеет компоновкой, `PwaStatus.astro` — логотипом и меню состояния. Header flex: бренд с min-width:0 и ellipsis, controls с фиксируемой шириной; иконки в одинаковых hit areas. На мобильных (до 60rem включительно) основное меню фиксировано снизу: repeat(4,minmax(0,1fr)), Избушка / Песни / Игры / Ещё. Summary «Ещё» занимает такую же ячейку, как ссылки. Одинаковая вертикальная геометрия, gap, размеры SVG и padding; активный раздел подсвечен. Учитывать safe area и отступ контента, не закрывать последнюю строку. На desktop меню в шапке: центральный блок `.header-navigation` объединяет основную навигацию и поиск, переключатель темы остаётся справа в `.header-actions`. На mobile навигация фиксирована снизу, единственный экземпляр Search остаётся в верхней шапке между брендом и темой с горизонтальными padding по .375rem и межблочным gap шапки. Не дублировать Search между breakpoint: его dialog и keyboard shortcut должны иметь одного владельца. Не возвращать «Частушки» в меню.

Контекстная шапка на всех ширинах: главная — «Масленица» / «Белград · дата» (дата из home.md, видна только при активном событии); остальные маршруты — заголовок текущей страницы из Starlight route data / «Масленица». Ссылка ведёт на главную. Семантический H1 сохраняется в контенте для доступности и поиска, но визуально скрыт; отдельная панель H1 не занимает высоту и не создаёт разделитель. На mobile основной контент начинается с .7rem отступа, поиск и sticky playlist компактнее. Нижняя навигация 3.65rem плюс safe area, одна резервная зона в main, без дублирующего padding на body; четыре равных ячейки сохраняются. Системная панель браузера не принадлежит приложению. Не менять утверждённые цвета.

## PWA status

Логотип использует оригинальный предоставленный владельцем векторный `/icon.svg` для шапки, favicon и PWA manifest. Не добавлять искусственную квадратную подложку. Размер frame 2.75rem desktop / 2rem mobile, object-fit:contain. Не привязывать геометрию к внутренним пропорциям SVG. Точка состояния в левом нижнем углу логотипа (не отдельная колонка); видима в standalone. Цвет: green online, blue offline + ready, red offline + unavailable, neutral gray unknown/download/delete. Приоритет busy над обычным состоянием. Не использовать accent киноварь для синего ready.

Единственный native popover `#festival-pwa-menu`, оба триггера используют один panel. Desktop — hover, keyboard focus, click; на mobile — tap по логотипу или status/⋮ первым блоком «Ещё». Позиционировать относительно фактического anchor: ниже верхнего логотипа при наличии места, выше нижнего триггера при необходимости, clamp к viewport. Не фиксировать экранные координаты и не наращивать z-index вместо top layer. Сохранять focus, Escape, light dismiss, повторный click; hover → click фиксирует уже открытое меню, а не закрывает его. На SPA swap закрывать menu и не оставлять ссылки на старые DOM nodes.

Пять строк с единой сеткой:
1. Подключение — Онлайн / Офлайн · копия доступна / Офлайн · копии нет / проверка.
2. Запуск — Браузер / Приложение.
3. Офлайн-копия — Готова / Устарела / Не скачана / Проверяем / Загрузка или Обновление N% / Удаление; рядом маленькая корзина.
4. Автообновление — двухпозиционный switch, без отдельной страницы для его включения.
5. Хранилище — оценка navigator.storage.estimate().usage всего origin, не точный размер pack.

Лейблы слева, значения и compact controls справа. Выравнивание строк по вертикальной оси, стабильные hit areas, текст может переноситься без горизонтального overflow. Не добавлять громоздкие action buttons, служебные сведения о регистрации SW или отдельную строку stage. Ссылка «Подробнее» и компактное действие Скачать/Обновить в footer. Прогресс по файлам, подпись «Прогресс · материалы», indeterminate до известного total. Тонкая линия занимает всю ширину внешней шапки Starlight от края до края, по её нижней границе (не по нижней границе внутреннего `.app-header` с padding). `.pwa-nav-progress` — sibling внутренней шапки; дорожка прозрачная, fill использует `--sl-color-accent` в обеих темах. Нативный progress стилизуется через appearance:none и WebKit/Firefox pseudo-elements, не только accent-color; indeterminate также использует акцент, с учётом prefers-reduced-motion. Те же цветовые правила действуют в popover, «Ещё» и на /offline/. Mobile status в «Ещё». В idle progress скрыт. Корзина disabled при отсутствии pack/staging, во время подготовки или удаления. Auto off сохраняет копию.

Presentation runtime получает модель из app.js; ни поповер, ни мобильное меню, ни /offline/ не определяют состояние самостоятельно. Storage estimate запрашивать по открытию/существенному изменению, не на каждом переходе.

## Песенник

Утверждённая композиция и rationale — [SONGS](SONGS.md). Общий sticky-плейлист, единые поверхности раскрытых песен, раздвижные капсулы и красные активные состояния сохраняются при изменении общих стилей. Общие токены: --festival-selected = #B5232C ночью и var(--festival-action) днём, --festival-selected-text = #FFFFFF; --festival-action — #C32935 ночью и #C43D32 днём. Не менять утверждённую светлую палитру при коррекции ночной темы. Не возвращать приглушённую заливку выбранных элементов. Геометрия проверяется отдельным модулем в production smoke.

## QA

Smoke проверяет desktop/mobile смену темы, hover/click/Escape, horizontal bounds меню при 390 px. Для layout-изменений обязательны реальные скриншоты/осмотр при 320, 390, 768 и 1440 px, обе темы, browser и standalone, длинные значения, loading/ready/stale/error и нижнее меню. Проверять одинаковые размеры четырёх hit areas, выравнивание корзины/switch и отсутствие скачков строк, clipping, наложений на theme/search и перекрытия контента. Проверить клавиатурный Tab/Shift+Tab, Escape и touch. Наличие smoke не подтверждает визуальную QA.

## Главная / Избушка

Постоянная часть: афиша бренда без просроченной даты, четыре ссылки (Песни / Игры / Сказ / Мастера), компактная галерея видимых персонажей, оригинальное предисловие и сворачиваемый краткий сюжет из Glide. Сезонная часть: год, дата, время, место и отдельная программа. Desktop: материалы и программа в двух колонках, заголовки и верхние/нижние края тела колонок совпадают; заголовок программы находится вне её рамки; при скрытии программы материалы занимают всю ширину. Mobile: одна колонка секций, 2×2 навигационные карточки, 3 колонки персонажей. Использовать существующие theme tokens; крупное оригинальное солнце на афише — `/media/maslenitsa-sun.webp`, при отсутствии файла на этапе сборки fallback на `/icon.svg`. Оба изображения локальные, входят в offline pack. Не добавлять декоративную рамку вокруг солнца; портреты локальные WebP из public/media/characters по character-archive.json; карточки 4:5 с изображением на всю площадь и акцентной плашкой имени, описания в native dialog без перехода. При отсутствии локального файла остаётся буквенный placeholder без внешнего запроса. Компонент CharacterGallery общий для главной и /characters/. Старые detail pages не генерируются. Не дублировать крупный заголовок Starlight (он остаётся доступным для screen reader).

Настройки — YAML frontmatter `src/data/home.md`: event.enabled, event.date (ISO YYYY-MM-DD в кавычках), event.timezone (Europe/Belgrade), event.schedule. Это единственный источник даты; event.json — адрес и координаты; schedule.json — HH:mm без даты. Программа отображается только при enabled && schedule && дата не прошла по календарю Белграда; день мероприятия включён целиком. Сезонные блоки SSR hidden, runtime `public/home-season.mjs` применяет состояние на cold/SPA/pageshow/visibility и каждые 30 секунд на открытой главной. Проверка локальная, без запроса к серверу. Программа не индексируется Pagefind отдельно от runtime. Изменения настроек требуют сборки, но естественное истечение даты работает и в старой offline копии. При отключении расписания остальные данные афиши сохраняются; при отключении события остаются материалы и постоянная афиша. Тесты: scripts/test-home-season.mjs и production smoke.
