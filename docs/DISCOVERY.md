# SEO, Open Graph и AI-friendly content
Референс — Antiokh/rslive.ru: astro/config/llmld.config.mjs, astro/src/components/SeoHead.astro, astro/integrations/static-og-images.mjs, starlight-llms-txt. Здесь данные находятся в JSON и Astro splash pages, поэтому экспорт строится непосредственно из src/data, а не только из Starlight content collection.
- Canonical base: https://masljanica.pages.dev (astro.config.mjs). При появлении собственного домена изменить site в config и site-content.mjs, ссылки календаря и перепроверить sitemap.
- Иконки генерируются из public/media/maslyanica-sun.webp (тот же логотип, что в шапке): PNG 96, ICO 16/32/48, Apple 180, PWA 192/512, отдельная maskable 512 с безопасными полями. Старый icon.svg оставлен для совместимости.
- Статические OG PNG 1200×630 для всех канонических маршрутов, title из данных, оригинальное солнце. Absolute URLs, og:image dimensions, twitter large image, единый theme palette. Никакого runtime renderer. Для малой базы кэш RSLive не требуется.
- AppHead: WebSite, WebPage/CollectionPage, BreadcrumbList, Event только для актуальной даты с известным расписанием, ItemList рецептов, отдельный llmld:AIWebsite на главной. JSON-LD и canonical HTML остаются доступными без JS.
- /llms.txt — индекс разделов и канонические ссылки; /llms-small.txt — краткий контекст; /llms-full.txt — полный текст; /_llms-txt/{festival,songs,games,scenario,workshops,pancakes,history,ditties}.txt — тематические фрагменты. Статусы мастер-классов, исторические источники, атрибуция частушек и ссылки на локальные записи сохраняются. Дата из home.md, не считать прошлую программу будущей. Лицензия RSLive не переносится.
- /robots.txt и /sitemap-index.xml: только канонические материалы, исключены legacy redirects и служебные страницы.
- npm run build: prebuild генерирует discovery assets; после Astro build check-discovery.mjs проверяет маршруты, head, размеры картинок и AI corpus. Затем build-offline.mjs формирует pack без дублирующих OG/AI-файлов; иконки PWA в pack.
- Не добавлять неподтверждённые даты, авторство, условия лицензии, рейтинги и регистрацию. Проверять итоговый HTML, фактическую PNG-типографику и превью в клиентах; успешная сборка не гарантирует моментальное обновление кэшей соцсетей.

Название PWA «Масляница»; фон manifest и непрозрачных Apple/maskable иконок #101827. Динамический meta theme-color следует CSS-теме или Telegram. SEO-имя фестиваля и OG-дизайн не меняются. См. PWA.md.

OG-композиция: крупный заголовок страницы слева, солнце справа, внизу общая информационная плашка с датой (включая год), временем при наличии расписания и адресом площадки. Все значения из site-content.mjs (home.md, event.json, schedule.json), актуальные только до даты мероприятия включительно. При отключённом или прошедшем событии — нейтральная подпись без даты. renderOgSvg вынесен в scripts/og-layout.mjs; проверяются сезонный и постоянный варианты. URL изображений стабильны, социальные сети могут сохранять старые превью в кэше.

Как в RSLive: для каждой страницы публикуются две последовательные группы og:image: 1200×630 (/og/) и 1080×1080 (/og-square/). Twitter использует горизонтальную. Горизонтальная композиция — данные мероприятия вверху слева, под ними заголовок и сокращённый description страницы, солнце справа почти во всю высоту. Квадратная композиция отдельно адаптирована: дата/место сверху, крупное солнце и читаемый заголовок с описанием. Оба формата исключены из offline pack. Проверяются размеры, порядок OG-тегов и сезонные сведения; соцсети выбирают подходящий формат самостоятельно.

Дата, время и адрес в обоих OG-форматах размещаются прямо на общем кремовом фоне, без отдельной цветной подложки; иконки и позиции текста сохранены.

Расширенная семантика: SEO-title отдельно от UI и OG, современные запросы «Масленица» при сохранении бренда. Общие исторические markdown и festival-plot.md используются в интерфейсе/AI. Генерируемые страницы /history/{chapter,name}/, /scenario/plot/, /pancakes/{id}/, /faq/, /sources/, /glossary/ имеют собственный canonical и метаданные. /festival.json и /knowledge.jsonld — машинные публичные данные. OG адрес включает Beograd, Srbija из event.json. Источники в knowledge-content.mjs. Не обещать rich results; неполные исторические рецепты не дополнять выдуманными ингредиентами.
