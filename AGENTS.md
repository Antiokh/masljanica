# Правила работы с Masljanica

Этот репозиторий — статическое приложение Astro + Starlight, с SPA-навигацией и полноценной PWA-копией. Существующие продуктовые решения являются контрактами, а не временными деталями реализации.

## Перед изменениями

1. Прочитать [README](README.md) и соответствующий контракт:
   - [PWA и навигация](docs/PWA.md) — Service Worker, cache, обновления, lifecycle, внешние эмбеды.
   - [Layout и интерфейс](docs/LAYOUT.md) — шапка, меню состояния, нижняя навигация, темы.
   - [Игры](docs/GAMES.md) — фильтры, аккордеоны, схемы, локальное сопровождение.
   - [Песенник](docs/SONGS.md) — локальные MP3, транспорт, очередь, раскрытие текста.
2. Если задача затрагивает перенос из RSLive, сначала сверить актуальные исходники и документацию [Antiokh/rslive.ru](https://github.com/Antiokh/rslive.ru), в частности `astro/docs/PWA.md`, `astro/docs/components/layout.md` и `astro/docs/components/map-embed.md`. Не копировать map-specific или Workbox-реализацию механически.
3. Проверить текущий HEAD и параллельные изменения перед записью. Не заменять целый файл старой версией. Не удалять сохранённые данные/маршруты вне задачи.

## Обязательные инварианты

- Название бренда и фестиваля — «Масляница» (через Я), в том числе в падежах. В SEO-title, исторических материалах и пояснениях допустимо современное написание «Масленица» для поискового намерения. Исторические цитаты, оригинальные названия и тексты песен сохранять без орфографической правки.

- Не возвращать полную перезагрузку при обычных внутренних переходах, блокирующие cache writes, network-first для точных cache hits или скачивание полной копии при установке Service Worker.
- Не объединять browser install, согласие на хранение, автоматические обновления, readiness и явное удаление данных в один флаг.
- Не активировать неполную копию; не удалять активную копию до успешной активации новой; сохранять staging для повторной попытки.
- Не добавлять вторую state machine для PWA UI. Меню, progress и отдельная страница читают состояние одного контроллера.
- Не заменять меню состояния одиночной ссылкой/точкой или набором больших кнопок; не ломать равную ширину четырёх нижних пунктов.
- Контекстный заголовок страницы в шапке, H1 сохраняется семантически без отдельной видимой панели; одна резервная зона под компактной нижней навигацией. См. docs/LAYOUT.md.
- Глобальный поиск — Pagefind index + FestivalSearch SSR dialog и единый SPA-safe controller; не возвращать DOMContentLoaded-only mount, сохранять metadata cache-buster compatibility и проверять cold offline search.
- Telegram Mini App интегрировать через runtime-environment.mjs; обычный браузер/PWA не загружает Telegram SDK, auto в Telegram следует colorScheme и themeParams (включая смену цветов внутри той же схемы), explicit темы сохраняются; не сводить Telegram auto к выбору двух фирменных палитр. Один PWA контроллер и один диалог поиска, без обещаний сохранности WebView cache. См. docs/LAYOUT.md и docs/PWA.md.
- Telegram Back: единый `telegram-back.mjs`, контракт DOBRI (overlay first, peer roots, один history guard, root close), адаптированный к Astro replace. Не добавлять независимые обработчики Back на страницах и не менять browser/PWA history. См. docs/LAYOUT.md.
- Не возвращать внешние iframe при холодном offline. Локальные аудио и текст остаются доступны.
- Песенник утверждён: верхний sticky-плейлист и капсулы используют один скрытый audio; не возвращать внешний аудиохостинг, dropdown, стандартные видимые audio controls, отдельные audio на строках или зависимость playback от раскрытия текста. Сохранять единый фон раскрытой карточки, контраст, круговой прогресс и независимую перемотку. См. [продуктовый контракт](docs/SONGS.md).
- Главная: единственный источник даты события — frontmatter src/data/home.md; сезонное отображение вычисляется локально по Europe/Belgrade, включая день мероприятия. Постоянные материалы доступны после даты. См. [layout](docs/LAYOUT.md#главная--избушка).
- Раздел «Частушки» восстановлен по явной задаче владельца: единственная навигационная точка на главной — приглушённая ссылка «…частушки?» справа от «В нашей избушке». Не добавлять плитку, пункт меню или редактуру исходных стихов без отдельной задачи; раздел доступен офлайн. Авторский корпус и анонимный фольклор разделены по файлам; источники и номера обязательны. См. [DITTIES](docs/DITTIES.md). CRM и непубличные данные не публикуются.

- Персонажи только в сказе: все записи characters.json (включая legacy show=false), локальные WebP, CharacterGallery, акцентное имя поверх портрета и native dialog; не возвращать навигацию на detail pages или внешний источник изображений.

- Игры: сохранять независимые фильтры, исходные правила и локальное сопровождение без автоперехода к следующей игре. См. [GAMES](docs/GAMES.md).

- Мастерские: иллюстрированная витрина, независимые фильтры, раскрытие на всю ширину под фактическим рядом; локальные иллюстрации, неподтверждённые занятия отдельно. См. [WORKSHOPS](docs/WORKSHOPS.md).

- Сказ: одна страница с отдельной историей праздника, тремя раскрываемыми частями, оригинальными репликами, локальными портретами и музыкальными вставками без автоперехода. См. [STORY](docs/STORY.md).

- Дополнения миграции из скриншотов: [GLIDE-MIGRATION-NOTES](docs/GLIDE-MIGRATION-NOTES.md). Сохранять историю, календарь, бесплатный вход и добровольный донейшн, не выдумывать ссылки.

## Перед merge

Запустить `npm test`, `npm run build`, затем production browser smoke (`node scripts/smoke-offline.mjs`, Playwright/Chromium). См. [матрицу проверок](docs/PWA.md#проверки-и-границы-подтверждения). Для визуальных изменений дополнительно проверить реальные desktop/mobile размеры, обе темы и клавиатурное управление. Тесты не ослаблять ради зелёной сборки.

Изменение контракта требует соответствующего изменения документации и тестов в том же PR/коммите; существенные изменения продуктового поведения согласовываются с владельцем. Если запуск невозможен, явно указать, какие проверки не выполнялись, и не объявлять production проверенным.

- Песни, игры, рецепты: desktop master-detail от 60rem, mobile native details. Общий catalog-master.mjs поверх SSR карточек, без копий контента/аудио. Высота правой панели естественная, скролл страницы; список слева ограничен её высотой. Проверять фильтры, hash, SPA, breakpoint, панели и cold offline.

- Discovery/SEO: src/lib/site-content.mjs — единый граф страниц, дата из home.md, source data. build-discovery.mjs генерирует PNG OG, иконки и llms; check-discovery.mjs валидирует dist. Не переносить лицензию RSLive без решения владельца. OG/LLM/sitemap не включаются в офлайн-пакет, PWA-иконки включаются. См. docs/DISCOVERY.md.

## Старт нового AI-чата: контекст проекта
- Репозиторий Antiokh/masljanica, ветка main, production https://masljanica.pages.dev/, Cloudflare Pages. Node >=22.12, Astro 5 + Starlight 0.35, статический HTML, vanilla ES modules, sharp для ассетов. Не менять стек без задачи.
- Народный волонтёрский фестиваль в Белграде и круглогодичная библиотека традиций. Основной язык русский. Бренд «Масляница», современный поисковый вариант «Масленица», Maslenica / Maslenitsa. Название установочного PWA просто «Масляница». Дата определяется только home.md; на момент записи 14.03.2027, 11:30–16:00, Roštilj zona, Ada Ciganlija, Beograd, Srbija. Бесплатный вход, добровольный донейшн. Проверять текущие данные, не закреплять дату в коде.
- Визуальный язык: оригинальное иллюстрированное золотое солнце public/media/maslyanica-sun.webp, народная тёплая эстетика, кремовые OG, акцент кармин/терракота, тёмная тема #101827, светлая #FFFFFF, Telegram динамическая палитра. PWA manifest fallback dark; не менять логотип и утверждённый стиль. OG 1200×630 и 1080×1080, шапка сверху без отдельной подложки, дата/время/место включая страну, description страницы, солнце крупное. Квадратный альтернативный og:image после landscape. - Source data src/data: home.md, event.json, schedule.json, socials.json, songs.json, games.json, game-details.json, characters.json, scenario.json, parts.json, workshops.json, workshop-details.json, pancake-recipes.json, history-chapters.json, ditties.json, ditties-folk.json и архивы локальных ассетов.
